# ADR 0012 — Deposits, ledger and statement matching (Sprint 5a)

**Status:** Accepted

| Decision                                                                                                                                                                                                                                                                                                                   | Rationale                                                                                | Alternative considered            |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- | --------------------------------- |
| Deposits paid by EFT into Thabekhulu's trust account, each with a unique reference `TDG-D-<bidder>-<4 chars><check>` from an alphabet without look-alikes (no I, O, 0, 1)                                                                                                                                                  | Works for any amount, no provider fees; references survive being typed into banking apps | Gateway for all deposits          |
| Check character uses **odd** position weights (invertible mod 32): every single-character typo is detected, proven over 57 300 typos; even weights let some typos through (found in review)                                                                                                                                | A mistyped reference never matches someone else's deposit                                | No check character                |
| Append-only `ledger_entries` in cents; updates and deletes throw; balances are always the sum of entries; corrections are new entries (P2)                                                                                                                                                                                 | Auditable money trail                                                                    | Editable balance column           |
| Bank statement import (CSV with header detection incl. credit/debit columns, semicolons, day-first dates, SA number formats; OFX): exact outstanding amount with a valid reference confirms automatically; **short, over and unknown payments always go to a finance queue** and are applied or dismissed only with a note | Never confirm money that doesn't add up                                                  | Auto-apply partials               |
| Each statement file and each line is fingerprinted (identical lines in one file are numbered); overlapping statements never double-count                                                                                                                                                                                   | Banks export overlapping date ranges                                                     | Trust finance to avoid re-imports |
| Confirmation runs in a transaction with a row lock on the deposit; issues a gap-free receipt `TDG-R-YYYY-NNNN`, emails it as a PDF, and **locks the refund account**                                                                                                                                                       | Exactly-once confirmation; refunds can't be redirected                                   | —                                 |
| Compliance gate enforced on the server: no deposit until all five compliance items are signed off (P4)                                                                                                                                                                                                                     | Listings can't take money before legal checks                                            | Warning only                      |
| "Deposit received" is a blocking bidder-approval item; buyers can pay once they've applied (pending), so payment can precede approval                                                                                                                                                                                      | No deadlock between approval and deposit                                                 | Approve first                     |
| Money on screens uses the shared `rand` / `randCents` formatters, never `toLocaleString`: browsers format `en-ZA` with a decimal comma while the server renderer doesn't, which broke hydration and would have shown wrong amounts (found in testing; guarded by a test)                                                   | Same text on server and browser; correct amounts                                         | Locale formatting                 |
| Receipt states the deposit terms from the listing's `DepositTerms` enum value (a string comparison against the enum stated the wrong terms; found in visual check, now tested for both terms)                                                                                                                              | A receipt must state the legal terms correctly                                           | —                                 |
