# ADR 0015 — Bid engine (Sprint 6a)

**Status:** Accepted

| Decision                                                                                                                                                                                                                                                                                                                    | Rationale                                                                | Alternative considered |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ | ---------------------- |
| One `BidEngine::place()` accepts every bid inside a transaction holding a row lock on the listing's `auction_states` row (B4)                                                                                                                                                                                               | Bids for a listing are processed strictly one at a time; no lost updates | Optimistic retries     |
| Proxy resolution (B3): with challenger maximum E and leader maximum L, E > L makes the challenger leader at max(their bid, min(E, L + increment)); E ≤ L keeps the leader, who answers with min(L, E + increment); equal maximums go to the **earlier** maximum; every resulting bid is recorded, automatic ones as `proxy` | Standard, explainable proxy bidding; tested on the exact bid sequences   | —                      |
| The leader cannot bid against themselves; they may only raise their maximum (which keeps its original time for ties)                                                                                                                                                                                                        | Prevents accidental self-raising                                         | Allow self-bids        |
| Maximums stored encrypted and never sent to the browser or the staff monitor                                                                                                                                                                                                                                                | Bidders' maximums are private (B3)                                       | Visible to staff       |
| Eligibility is re-checked inside the lock on every bid: approved for this listing, deposit received, verification in date, clear screening in 30 days, open listing, not paused, not closed; staff can never bid (B1). Seller-linked checks apply when the seller module is enabled (Phase 1 listings are admin-listed)     | A bidder who loses eligibility mid-auction stops immediately             | Check at approval only |
| Increment bands from settings (placeholders until Thabekhulu confirms); first bid ≥ minimum; bids binding (B2)                                                                                                                                                                                                              | —                                                                        | Free amounts           |
| Soft close from the existing settings: an accepted bid inside the window moves the close to now + extension (B5)                                                                                                                                                                                                            | —                                                                        | Fixed end              |
| Step-up code (B6) when a bid or maximum ≥ min(threshold setting, 2 × minimum): 6-digit code **emailed** (hashed, 10 minutes, 5 attempts, single use) until an SMS provider is chosen                                                                                                                                        | Works without new providers                                              | SMS only               |
| Bids are append-only; voiding (B9) sets `voided_*` once with a reason, voids that bidder's maximum, and resets the state to the last valid bid                                                                                                                                                                              | Errors fixed transparently and audited                                   | Delete bids            |
| Pause rejects bids; resume moves the close by the paused time                                                                                                                                                                                                                                                               | Fair to bidders                                                          | Fixed close            |
| Public view sends bidder numbers, amounts and SAST times only (tested: no names, no maximums); polls every 5 s until 6b adds WebSockets                                                                                                                                                                                     | B7                                                                       | —                      |
| Comparisons with enum columns use `->value` (`auction_type` is an enum; the 5a receipt bug class)                                                                                                                                                                                                                           | —                                                                        | —                      |
| **Settings cache is cleared after every migration run** (both `MigrationsEnded` and `NoPendingMigrations`): a deployment that added a setting otherwise served a stale cached copy and broke pages (found in the visual check)                                                                                              | Deployments can't serve stale settings                                   | Manual cache clears    |
| Concurrency under real parallel load (simultaneous last-second bids) is proven in the Sprint 6c load test on MySQL                                                                                                                                                                                                          | Needs multiple processes, not a unit test                                | —                      |
