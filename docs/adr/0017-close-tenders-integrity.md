# ADR 0017 — Auction close, sealed tenders and integrity checks (Sprint 6c)

**Status:** Accepted

| Decision                                                                                                                                                                                                                                                                                                                                                                                                                         | Rationale                                                           | Alternative considered |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- | ---------------------- |
| New listing statuses **Closed** (results being determined; tenders await opening), **Sold** (pending settlement) and **No bids**. `isPublic()` stays Scheduled/Live because it gates applying, deposits and data rooms; `isShown()` keeps finished auctions visible on their own page with the outcome. Pricing and times are locked after the close (a `match` that would have crashed on the new statuses was found and fixed) | Clear lifecycle; nothing can be paid or applied for after the close | Reuse Live             |
| `auctions:close` every minute: considers live listings whose **original** end has passed (extensions only move the live end later); under the bid lock it re-checks the live end and the pause, then records winner (leader) and runner-up (highest valid bid by a different bidder). Idempotent; one result per listing                                                                                                         | Soft close can never be cut short; repeated runs are harmless       | Fixed close time       |
| Deposit hand-off at close: winner's deposit kept for settlement; runner-up's refund scheduled after the hold period; everyone else's scheduled for refund; unpaid applications ended; result emails sent. A deposit that cannot be scheduled is logged and audit-recorded and the close **continues for everyone else** (found in testing: one bad deposit aborted the whole run)                                                | One problem never blocks other bidders' refunds                     | Fail the close         |
| Sealed tenders (B8): offers encrypted with the application key, raise-only (only ever compared with the same bidder's previous offer), refused after the deadline; staff see only the count; opening needs a request and a confirmation by a **different** person; highest offer wins, ties to the earlier offer. The bidder sees only their own offer (tested)                                                                  | Confidential, fair tenders                                          | Visible offers         |
| Integrity checks for review (never automatic action): shared IP between bidders, shared refund bank account (compared after decryption), shared controllers across bidding entities, and "pumping" (3+ bids each answered by the same bidder, never winning)                                                                                                                                                                     | Shill bidding is spotted by a person                                | Automatic suspension   |
| Step-up codes move to a shared `StepUp` class used by bids and tender offers                                                                                                                                                                                                                                                                                                                                                     | One rule                                                            | Duplicate logic        |
| Date-typed helpers accept `CarbonInterface` (the app uses immutable dates; a helper typed for mutable `Carbon` crashed the edit page for closed listings; no others found)                                                                                                                                                                                                                                                       | —                                                                   | —                      |
| **Concurrency proven** with `tests/Load/concurrent-bids.php`: 40 forked processes, 1 000 simultaneous bid attempts inside the soft-close window, on MySQL with live Reverb broadcasts. All invariants hold in every run (amounts never decrease, state equals the bids, leader is the last bidder, soft close correct, the close records exactly that winner, every other deposit handed to refunds)                             | The row lock works under real contention                            | —                      |
| Latency: a single bidder's bid takes p50 4 ms / p95 9 ms including the broadcast. Under 40 parallel bidders this sandbox (**1 CPU**) measures CPU queueing (p95 about 450 ms), not the engine. The spec's 300 ms p95 under 500 bidders / 2 000 viewers is therefore **measured in Sprint 9 on multi-core staging hardware**. The feed snapshot is now built after the commit so other bidders don't wait on the lock for it      | Honest about what this environment can and cannot show              | Claim the target       |
