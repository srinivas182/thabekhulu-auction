# ADR 0021 — Premium slots, badges and public results (Sprint 7d)

**Status:** Accepted

| Decision                                                                                                                                                                                                                                                                                                                                                                               | Rationale                            | Alternative considered    |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------ | ------------------------- |
| Admin-assigned premium slots (S10): listing, its category, optional city (none = whole category), position 1–3, dates; overlapping slots for the same position and place are refused, as is a second overlapping slot for the same listing in the same place; only listings on the website; paid booking stays Phase 2                                                                 | PRD Phase 1 premium                  | Free-form "featured" only |
| When browsing a category, active slots sort first by position (whole-category slots always; city slots only with that city filter), then the chosen sort                                                                                                                                                                                                                               | Premium placement where it is sold   | Separate premium strip    |
| Slot dates compared with `DATE()` in raw SQL: SQLite stores the date cast with a time and compares as text, so a slot starting today was not active (found in testing); MySQL truncates, but the query must be correct on both                                                                                                                                                         | Portable date logic                  | Database-specific SQL     |
| Badges computed, never stored: Premium (active slot, or the legacy featured flag), New (auction opened within the setting's days), Hot (bid count at or above the setting), Renovated (deal type)                                                                                                                                                                                      | Always current                       | Stored flags that drift   |
| Public sold result (PRD): price, date and **bidder number, never a name**; after a default, the runner-up's price and number once they have accepted; Mining keeps the "Preferred bidder: subject to approvals" wording with the bid shown                                                                                                                                             | Transparency without exposing buyers | Hide the price            |
| No-bids listings are hidden from the website (detail page returns 404) and can be **relisted** (`listings.publish`): old bids and maximums voided with "Relisted" (append-only record kept), auction state, result and tender data cleared, earlier applicants asked to re-apply, listing back to Draft; a relisted auction closes again without clashing with the old result (tested) | PRD: hidden, relistable              | Clone the listing         |
