# ADR 0026 — Data retention (Sprint 9a, part 2)

**Status:** Accepted (schedule pending attorney approval)

| Decision                                                                                                                                                                                                                                                                                                                                                                                                                              | Rationale                                                    | Alternative considered |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ | ---------------------- |
| A retention schedule in code (`RetentionSchedule`): KYC records and their files 5 years after the relationship ends (FIC Act record-keeping); data-room download logs 5 years; unconverted leads 2 years after last activity; unconfirmed newsletter sign-ups 30 days; unsubscribed records 2 years; ticket holders' details anonymised 2 years after the event (amounts kept). Every basis marked "to confirm" for the attorney (H6) | POPIA: keep no longer than necessary; FICA: keep long enough | Keep everything        |
| A relationship ends at deactivation, or otherwise at the last sign-in; **anyone with an open deposit or settlement is never included**                                                                                                                                                                                                                                                                                                | Never remove records still in use                            | Account age only       |
| **Financial records are never touched** by this job (ledger, receipts, invoices, payouts, refunds); accounts remain; KYC files are deleted from storage before their rows                                                                                                                                                                                                                                                             | Tax law requires keeping financial records                   | Delete whole accounts  |
| **Report-only until approved**: `privacy:retention` reports (and audit-logs) what is due; `--purge` and the weekly scheduled run purge only after a super admin records the attorney's approval reference (audited)                                                                                                                                                                                                                   | No deletion without legal sign-off                           | Purge immediately      |
| Ticket holders are anonymised row by row in PHP (portable; `CONCAT` isn't available in every SQLite)                                                                                                                                                                                                                                                                                                                                  | Same behaviour on every database                             | Database-specific SQL  |
| **The scheduler never reads settings at start-up**: an earlier version did, which made every artisan command fail before the new settings existed, **including the migration that creates them**; a regression test now starts the scheduler with the settings missing                                                                                                                                                                | Deployments can't deadlock on their own migration            | —                      |
