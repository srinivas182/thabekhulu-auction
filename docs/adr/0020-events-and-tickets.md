# ADR 0020 — Events and QR tickets (Sprint 7c)

**Status:** Accepted

| Decision                                                                                                                                                                                                                                                                                                                                                      | Rationale                                               | Alternative considered |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- | ---------------------- |
| Events are free or paid, online or in person, with a capacity; drafts are not public; the online link is shown only to ticket holders                                                                                                                                                                                                                         | PRD events                                              | —                      |
| Ordering takes a row lock on the event; seats taken = paid and free tickets plus pending card payments **within their 15-minute hold**; at most 4 tickets per order; POPIA consent and a honeypot on the public form                                                                                                                                          | No overselling; abandoned checkouts release seats       | Count only paid        |
| Paid tickets reuse the Sprint 5b Paystack integration: hosted checkout with an `order_reference`, signed webhook, every charge verified with Paystack, tickets issued only when the paid amount matches exactly; payments arriving after the hold are honoured and logged                                                                                     | One payment path, same safeguards as deposits           | New gateway code       |
| QR content `TDGT1.<ticket ulid>.<HMAC signature>` with the application key: unforgeable, re-displayable at any time, nothing secret stored; door code of 8 characters without look-alikes for typed entry                                                                                                                                                     | Tickets can't be faked; buyers can reopen their tickets | Random stored secrets  |
| Tickets by email as an A4 PDF (QR + door code per ticket) and on a **signed** tickets page                                                                                                                                                                                                                                                                    | Works offline at the door                               | Email text only        |
| Check-in is one atomic update (`checked_in_at` set only if empty): two scanners can never both admit a ticket; results admitted / already used (with time) / invalid / another event; phone camera via `qr-scanner` (works in iPhone Safari, unlike the browser BarcodeDetector) or typed code; camera already allowed by `Permissions-Policy: camera=(self)` | Fast, single-use entry at the door                      | Paper lists            |
| Signature check is case-insensitive and the code box no longer upper-cases input: found end to end (QR decoded from the real page) when typed or scanner-gun entry of the QR text was rejected                                                                                                                                                                | Every entry method works                                | —                      |
