# ADR 0025 — In-house security review (Sprint 9a, part 1)

**Status:** Accepted

| Decision                                                                                                                                                                                                                                                                                                                                                                       | Rationale                               | Alternative considered |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------- | ---------------------- |
| Review against OWASP ASVS 4.0 level 2 (H3), recorded as a findings register with evidence and status in `docs/security/asvs-l2-review.md`; explicitly an in-house review that supports the independent penetration test (9c)                                                                                                                                                   | Traceable, honest scope                 | Informal checklist     |
| Route protection is **tested, not assumed**: every admin route must carry sign-in, staff, staff two-factor and IP-allowlist guards plus a `can:` permission or a documented exception (the three settlement view routes check permissions in the controller); a staff member with no permissions is refused on every parameter-free admin page; buyers and guests are kept out | Protection stays true as the code grows | Manual review only     |
| Dependency advisories: `composer audit` and `npm audit --omit=dev --audit-level=high` run in CI and fail the build; both clean today                                                                                                                                                                                                                                           | Known-vulnerable packages can't ship    | Periodic manual checks |
| Session cookies **default to HTTPS-only in production** (previously off unless `SESSION_SECURE_COOKIE` was set)                                                                                                                                                                                                                                                                | A forgotten setting is safe             | Rely on configuration  |
| `php artisan security:check` fails on debug mode, the test-suite application key, a non-HTTPS URL, insecure or unencrypted sessions, log-only mail, synchronous queues and a non-Reverb broadcaster; the deployment guide runs it before go-live                                                                                                                               | Misconfiguration caught before launch   | Checklist on paper     |
| Secrets scan of the full git history: no credentials committed; the only key present is the test-suite key in `phpunit.xml`, which `security:check` refuses in production. Development credentials (including the shared GitHub token) must be rotated before launch (H8)                                                                                                      | —                                       | —                      |
| All 18 upload rules restrict type (content-based) and size; SVG is rejected for images; virus scanning left optional until the hosting choice                                                                                                                                                                                                                                  | —                                       | —                      |
| Open: retention purge (V8) pending attorney approval of the schedule (H6), to be built report-only first; TLS verification on the real host (9d)                                                                                                                                                                                                                               | —                                       | —                      |
