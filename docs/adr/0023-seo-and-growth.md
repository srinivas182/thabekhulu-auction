# ADR 0023 — SEO/AEO and growth (Sprint 8b)

**Status:** Accepted

| Decision                                                                                                                                                                                                                                                                                                                                                                                                                                             | Rationale                                      | Alternative considered     |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- | -------------------------- |
| One `SeoHead` component (rendered on the server via SSR) for description, canonical, Open Graph (site name, locale, type, title, description, URL, image) and Twitter card; a `Seo` helper makes every URL and image absolute. Used on listings (completing tags that lacked type, URL, site name and card), events and the home page. Verified by fetching pages as a crawler would: all tags in the server HTML                                    | Link previews in WhatsApp, Facebook and search | Per-page hand-written tags |
| Structured data (T4): listings keep `RealEstateListing` + breadcrumbs (seller shown as Thabekhulu, no internal prices); events get `Event` with attendance mode, location (a `VirtualLocation` pointing at the event page, **never the private meeting link**), dates, organiser and an `Offer` with availability; home gets `Organization` and `WebSite`. **No `SearchAction`**: the site has no free-text search and advertising one would mislead | Answer engines get accurate, safe facts        | More schema types          |
| Sitemap adds the events list and published upcoming events (drafts excluded)                                                                                                                                                                                                                                                                                                                                                                         | Discoverability                                | —                          |
| Saved searches (G1): up to 10 per buyer, filters limited to the public search's own keys; **matches existing at save time are recorded so only new listings are alerted**, each once per search; hourly `growth:alerts`                                                                                                                                                                                                                              | No noise, no repeats                           | Daily "all matches" email  |
| Watchlist (G1): buyers follow listings; a reminder once, within 24 hours of the close, only to watchers who are not already bidding (bidders get their own alerts)                                                                                                                                                                                                                                                                                   | Useful, never duplicated                       | —                          |
| Share links (G1): WhatsApp, email and copy, tagged `utm_source=share&utm_medium=<channel>&utm_campaign=listing`; first-touch `utm_*` kept in the session and saved on the account at registration (`forceFill`, since the model's fillable list would silently drop it)                                                                                                                                                                              | Measurable growth                              | Analytics-only             |
| Newsletter (G1): POPIA double opt-in with a 7-day signed confirmation link, signed unsubscribe link, honeypot and rate limit; **the same reply whether or not the address is already subscribed**, so the form can't reveal subscribers; confirmed subscribers exported (CSV with unsubscribe links) by `cms.manage` staff for the chosen mailing tool                                                                                               | Lawful, private                                | Single opt-in              |
| An edit to the listing controller once matched the wrong `'seo' => [` block and deleted part of two methods without any syntax error; it was caught by inspection, the file restored and the edit redone scoped to `show()`. Lesson: anchor text edits to the method they belong to                                                                                                                                                                  | —                                              | —                          |
